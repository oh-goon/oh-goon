# Execution-environment tool authority

The resolved Step is the declaration of need: `uv run pytest` requires `uv`, a Git step requires `git`, `oci_build` requires its typed build tool, and so on. Canonical Oh-Goon `make` workloads derive child executable need from the selected Make/script/npm/package-bin authority. That discovered need is **not permission**. `backend/goon-execution-requirements.json` owns only an independent `workload_tool_permissions` ceiling keyed by the derived `make:<target>` workload owner; it does not restate compiled Step facts. Static admission requires derived need to be a subset before work. `backend/src/oh_goon/canonical_goon_tool_authority.json` is generated transport of the exact admitted need into packaged canonical Steps; it is checked for staleness and grants nothing by itself. Canonical Goon YAML therefore does not mirror derived native tools in `tools.allow`. Non-canonical single-Step Goons may still use `tools.allow` as explicit positive child-tool permission.

The frozen run inventory is **not** ambient Step authority. Each physical attempt receives its derived primary executable, fixed typed companions, its exact admitted `capabilities.tools` children, and—only when that Step owns `sh`/`bash`—the fixed sandbox shell-support toolset. An `oci_build` Step requires both Buildah and crun: OCI isolation executes Containerfile `RUN` instructions through the frozen crun companion with `--network none`. Both executables and their native library closures are captured before execution. `execution.shell` in canonical Goon YAML is readable execution intent, not a bypass around the independent permission ceiling. Shell support is runtime-owned rather than hand-authored, but every support executable is still name-resolved, byte-frozen, hashed, and included in run evidence. The support set excludes authority-bearing tools such as `curl`, `git`, `npm`, and `uv`, and its exact membership participates in execution-authority identity. The same subset rule applies to imported host-environment values: preparation may freeze the run-wide union once, but sibling Steps do not inherit another Step's tools or secrets. Run-wide capture owns reproducibility/evidence; the Step plus fixed runtime-support contract own execution permission.


For image-backed executors, the pinned execution image is the intended toolchain owner; the current universal contract records the backend configuration identity rather than requiring pipeline tool declarations. For the local Bubblewrap backend, the native executor inventory supplies only an ordered operator-owned `tool_search_paths` under `trusted_host_roots`; oh-goon never inherits caller `PATH`. Authority attaches to the named directory entry in that admitted search path. A distribution-owned executable symlink may dereference outside the `bin/` directory (for example NVM's `npm`/`npx` links into the sibling npm package tree), but repository authoring still cannot name an arbitrary host path: only the admitted logical tool name is resolved, and the dereferenced executable bytes plus required runtime support are immediately frozen into the run-owned toolchain. The local backend freezes that exact executable/runtime closure into `/toolchain/bin` as an internal safety measure. That freeze is evidence, not authoring ceremony.

Canonical run evidence records the tools actually admitted/observed (name, digest, byte count and stable identity). Attempt evidence is cross-checked against that frozen run evidence. A conventional interpreter path such as `/bin/sh` is overlaid only when the current Step owns the frozen `sh` tool; it is not supplied merely because another Step in the run needs a shell. This keeps run debugging strong while keeping the authored CI/CD clear.

APP self-certification is not a fresh CI/CD attempt. Canonical `make init` owns local dependency/interpreter materialization once, and verification Plans execute against that initialized repository without rebuilding `.venv`/`node_modules`, selecting another interpreter, or reacquiring packages. Strict CI/CD attempts still own their `/workspace` namespace and frozen toolchain independently; that isolation contract must not be reused as a reason to discard already-established local APP initialization authority.

The contract has no closest-version selection, hidden install, PATH fallback, or runtime substitution. If a required executable is missing, Enforcer fails before the pipeline starts.
