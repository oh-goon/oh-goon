# T0B2A — Offline custody-review packet intake (not trust authority)

## Purpose and status

This checkpoint provides an **offline cryptographic intake verifier** for third-party
review material. It does not decide whether a signer/root is semantically necessary,
independently custodied, safe to merge, or approved for runtime admission. It **never**
sets `Gate A` to PASS, updates the registry, or imports an external review verdict
into Enforcer/LACE.

**Normative design-only registry:** `backend/trust-authorities.json` (source-backed,
not yet authenticated runtime trust). **Pending custody register:**
`backend/trust-custody-evidence.json`, still unreviewed and unchanged. **One generated
census:** `docs/architecture/TRUST_AUTHORITY_CENSUS.md`. T0B2A introduces no second
registry, signer, Run admission, sandbox, journal or qualification implementation.

## Offline review packet format

Supply the following in a **separate directory outside the source tree**:

- `review.json`: UTF-8 canonical `json.dumps(..., sort_keys=True, indent=2, ensure_ascii=False) + "\\n"` bytes
- `review.sig`: hex Ed25519 signature (lowercase, 128 hex characters, newline optional)
- 1–20 named evidence files, each at most 1 MiB, total at most 4 MiB

`review.json` contains exactly:

- `schema`: `oh-goon/offline-custody-review/v1`
- `policy_sha256`: SHA-256 of the **exact source** `backend/trust-authorities.json`
- `custody_register_sha256`: SHA-256 of the **exact pending** `backend/trust-custody-evidence.json`
- `subject`: exactly one currently registered custody-review subject
- `reviewer_id`: human label, not proof of real-world identity
- `disposition`: a *proposed* `KEEP`, `MERGE`, `EXTERNAL`, or `REMOVE`
- `rationale`: explicit review argument
- `observations`: the ten mandatory owner, custody, principal, compromise,
  security-benefit, provisioning, rotation and revocation assertions
- `evidence`: filename → SHA-256 digest for each exact file, no paths or aliases

The detached signature covers the exact raw `review.json` bytes prefixed with:
`oh-goon/offline-custody-review/v1\x00`. The reviewer's **raw 32-byte Ed25519 public
key** and its **SHA-256 fingerprint** MUST be supplied independently from the
packet by the review operator. The packet cannot designate its own verifier.
Private keys and raw secrets must not be placed in review packets or this source.
Do not use arbitrary keys generated by the subject as proof of independent review.

### Inspect outside the runtime

After preparing the backend environment through the normal locked process, run
this standalone declared utility from the `backend` directory:

```sh
uv run --no-sync oh-goon-offline-custody-review \
  --packet-dir /secure/intake/PACKET \
  --reviewer-public-key /secure/out-of-band/reviewer-ed25519.pub \
  --expected-reviewer-key-sha256 <INDEPENDENTLY_VERIFIED_64_HEX_FINGERPRINT>
```

It emits `AUTHENTICATED_REVIEW_PACKET_NOT_CUSTODY_PROOF` only when cryptographic,
byte-level and schema checks all pass. The report says `gate_a=BLOCKED`,
`runtime_authority=false`, `approval=NOT_GRANTED` and `T1_migration_authorized=false`.
Bad inputs exit nonzero. No runtime policy or source mutation occurs.

## Authority and evidence boundaries

A valid review packet is an authenticated *submission*. It is **not** an independent
confirmation of: (1) reviewer real-world identity, (2) custody separation,
(3) OS/process isolation, (4) signer necessity, (5) key provenance, or (6) physical
kernel-observer authority. These require external corroboration, conflicting-fact
review, OS-owned custody tests and explicit approval before T1/T2.

Actual host evidence cannot be synthesized in a hosted unit test. Synthetic test
Ed25519 keys and packets prove only implementation behavior. Runtime signer epochs,
revocation, six required issuer fields and the original `RESOURCE_INTENT` remain
untouched. Future T0B2B must review real independent records and record approved
semantic dispositions through a single exclusive, authenticated T1 migration.

## Anti-drift

The existing `check_architecture` gate requires the declared offline entrypoint,
signature checking on the direct intake call path, no-follow source reads, frozen
blocked outcome, QENV1 `AGENT_PREWORK` enrollment, and no import from runtime,
services, integrations or native issuer. Mutation regressions reject substituted
keys and packets, stale registry/register identity, fake fields, unregistered
subjects, traversal, aliases, changed source evidence, unsupported authority
approval and a hidden/dead-branch signature verification.
