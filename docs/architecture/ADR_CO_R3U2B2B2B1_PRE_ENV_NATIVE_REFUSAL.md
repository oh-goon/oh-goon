# ADR — Original native positive refusal before environment effects

## Context

QENV1 was executing a locked project environment preparation before it rejected a native CO-R3N positive-effect request. Because current LACE has no provisioned OS-exclusive writer custody, that request cannot lawfully run, even with a syntactically valid disposable cgroup path. The baseline CO-R3U2B2B2A rejection protects kernel effects but did not fail before non-kernel environment work.

## Decision

Move the **existing** positive-witness block to the original qualifier's pre-environment source-admission cut. Preserve original source PRE/POST and exact external manifest checking, then produce an explicit blocked status and return 3 before `uv sync` or any native CORE test. Keep the negative actual-Linux witness enrolled in precisely the same CORE ring for normal development qualification. Recognize this checkpoint's self-excluding source manifest instead of erroneously falling back to an earlier source identity. Guard ordering and refusal with the existing X0 authority contract and a focused executable Bash regression.

## Boundaries

No new qualification program, source inventory, kernel owner, external issuer, LACE permit, Enforcer decision, teardown actor, or Hashmarks diagnostic implementation. A source manifest cannot prove kernel custody or even independent code provenance. Host-exclusive custody and all real physical safety proofs remain CO-R3U2B2B2B2 and later real-host gates.

## Failure rules

If the legacy positive environment variable is requested on current source: emit `BLOCKED_NON_ISSUING_LACE`, never start `uv sync` or a native test ring, preserve source POST proof through the original EXIT trap, and return 3. Missing/altered source, missing host requirements, or unavailable Linux custody cannot convert into a release or physical PASS.

The existing QENV1 manifest precedence architecture contract must recognize the new source checkpoint, not only the older CO-R3T line, while retaining its historical B3B3B4 ordering negative control. This checker is updated in place; there remains one canonical selection and one checker owner.
